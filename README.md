## О проекте

**Errorium** — это специализированная интеллектуальная поисковая система, предназначенная для поиска программных ошибок, анализа стектрейсов и синтеза готовых решений на основе базы вопросов и ответов Stack Overflow.

Система решает проблему долгого поиска решений типовых и нетиповых ошибок разработки за счёт объединения ключевых подходов:
1. **Точный лексический поиск:** Самописный инвертированный индекс и ранжирование по алгоритму **BM25**, оптимизированный под синтаксис кода, имена исключений и стектрейсы.
2. **RAG-пайплайн (Retrieval-Augmented Generation):** Обогащение релевантного контекста через LLM для получения готового структурированного решения проблемы.
3. **Интеграция с AI-ассистентами (MCP):** Встроенный сервер протокола **Model Context Protocol (MCP)**, позволяющий современным кодинговым агентам (Cursor, Claude Code, Windsurf) вызывать Errorium напрямую из IDE.
4. **Интерактивный граф связанных тредов:** Визуализация связанных обсуждений Stack Overflow (дубликаты, ссылки в ответах) напрямую в результатах поиска.
5. **SSO и панель администрирования:** Единая точка входа (OAuth2 / OpenID Connect: GitHub, Google, корпоративный IdP), ролевой доступ (RBAC) и панель управления индексами и промптами.

## Академические требования (Кафедра ИУ5)

В соответствии с требованиями НИРС:
- **Никаких сторонних поисковых библиотек:** Категорически запрещено использование `Elasticsearch`, `OpenSearch`, `Lucene`, `rank-bm25`, `tantivy` и т.д. Инвертированный индекс и расчет метрик реализованы вручную.
- **Алгоритм ранжирования BM25:**
  $$IDF(t) = \ln\left(1 + \frac{N - DF(t) + 0.5}{DF(t) + 0.5}\right)$$
  $$BM25(q, d) = \sum_{t \in q} IDF(t) \cdot \frac{TF(t, d) \cdot (k_1 + 1)}{TF(t, d) + k_1 \cdot \left(1 - b + b \cdot \frac{|d|}{avgdl}\right)}$$
  *Параметры:* $k_1 = 1.5$, $b = 0.75$.
- **Межсервисный протокол:** Взаимодействие между Gateway и Search Engine происходит строго через **gRPC** по контракту `protos/search.proto`.
- **Токенизация кода:** Сохранение неделимыми идентификаторов ошибок (`NullPointerException`), кодовых путей (`fmt.Println`, `os.path.join`), утилит (`pip3`, `docker-compose`) и синтаксиса (`C++`, `.NET`).

## Быстрый старт

### Требования
- [Docker](https://docs.docker.com/get-docker/) и [Docker Compose](https://docs.docker.com/compose/)
- [GNU Make](https://www.gnu.org/software/make/)  
*(Все зависимости, среды исполнения и библиотеки изолированы в Docker-контейнерах)*

### 1. Запуск всех сервисов системы

Сборка образов и старт всех сервисов одной командой:

```bash
make up
# или напрямую: docker compose up --build
```

После старта доступны следующие интерфейсы:
- **Web UI:** [http://localhost:3000](http://localhost:3000)
- **REST API документация (Swagger):** [http://localhost:8000/docs](http://localhost:8000/docs)
- **Search Engine gRPC:** `localhost:50051`

Для остановки сервисов:
```bash
make down
```

## Разработка и тестирование

Все команды разработки обёрнуты в `Makefile` и выполняются внутри изолированных контейнеров:

### Генерация кода gRPC из Protobuf
При обновлении `protos/search.proto`:

```bash
make proto
```

### Запуск тестов
```bash
# Запуск unit-тестов
make test-unit

# Запуск интеграционных тестов
make test-integration

# Запуск всех тестов
make test
```

### Оценка качества поиска (Бенчмарк НИРС)
Проверка метрик качества ранжирования ($Recall@k$ и $MRR$):

```bash
make benchmark
```

## Методология разработки

Проект строго следует принципам **Spec-Driven Development (SDD)**. Любое изменение в коде обязательно проходит цепочку:  
`Документация (docs/)` $\rightarrow$ `Тесты (tests/)` $\rightarrow$ `Реализация` $\rightarrow$ `Бенчмарк` $\rightarrow$ `Лог (CHANGE_HISTORY.md)`.  
Подробные правила описаны в файле [AGENTS.md](AGENTS.md).
