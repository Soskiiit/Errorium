## 2. Протокол проверки Контрольной точки 2 (КТ 2): «Ядро поиска и RAG»

- **Срок по графику:** Ноябрь
- **Статус:** **ВЫПОЛНЕНО**
- **Ответственные:** Роль 1 (Indexer Engineer), Роль 2 (Core Search Engineer)

### Критерии приемки КТ 2:
- [x] **Самописный инвертированный индекс:** реализация SPIMI-индексатора (формат v1, бинарные posting lists) и базы связей `graph.db` (SQLite) в пакете `indexer`. Запрещены готовые библиотеки (Elasticsearch, Lucene, rank-bm25, Whoosh).
- [x] **Самописный алгоритм BM25:** расчет ранжирования строго по методическим указаниям кафедры ИУ5:
  $$IDF(t) = \ln\left(1 + \frac{N - DF(t) + 0.5}{DF(t) + 0.5}\right)$$
  $$BM25(q, d) = \sum_{t \in q} IDF(t) \cdot \frac{TF(t, d) \cdot (k_1 + 1)}{TF(t, d) + k_1 \cdot \left(1 - b + b \cdot \frac{|d|}{avgdl}\right)}$$
  Параметры: $k_1 = 1.5$, $b = 0.75$, $N$ и $avgdl$ извлекаются из `metadata.json`. Равные баллы упорядочиваются по возрастанию `doc_id`.
- [x] **Расчет метрик $Recall@k$ и $MRR$ через `benchmark/evaluate.py`:**
  Тестовый набор: 15 вопросов (10 answerable + 5 trap-запросов) на контрольном корпусе документов.
  - Порог NFR: $Recall@10 \ge 0.75$, $MRR@10 \ge 0.50$.
  - **Фактические зафиксированные метрики:**
    * **$Recall@3 = 0.9333$**
    * **$Recall@5 = 0.9333$**
    * **$Recall@10 = 0.9667$** (превышает порог $\ge 0.75$)
    * **$MRR@10 = 1.0000$** (превышает порог $\ge 0.50$)
- [x] **Интеграция с LLM для RAG:** модуль `rag.Orchestrator`, поддержка провайдеров `openai`, `gigachat` (с сертификатом НУЦ Минцифры) и `stub`, семафор `LLM_MAX_CONCURRENT=8` с graceful fallback на детерминированный шаблон.
- [x] **Межсервисный протокол:** gRPC сервисы `SearchService` и `GraphService` на порту `:50051`.

### Команды воспроизведения КТ 2:
```bash
# 1. Построение индекса контрольного корпуса:
make index-corpus

# 2. Запуск бенчмарка оценки качества ранжирования:
make benchmark
# или напрямую:
python3 benchmark/evaluate.py
```

## 4. Сценарий демонстрации системы (Demo Walkthrough)

Сценарий предназначен для воспроизведения на защите проекта перед комиссией:

1. **Запуск демонстрационного окружения:**
   ```bash
   make dev-docker
   ```
2. **Пользовательский сценарий в браузере (`http://localhost:3000`):**
   - **Гостевой поиск:** ввести ошибку `[Python] IndexError: list index out of range` в Prompt Bar. Получить карточку RAG-синтеза с кодом исправления и ссылками на источники SO.
   - **Интерактивный граф Star Map:** нажать кнопку `Star Map` в карточке ответа. Изучить подграф связанных тредов на Canvas: зеленый узел (Top-1 результат), желтые (Top-K), синие (дубликаты), фиолетовые (ссылки). Навести курсор для просмотра сниппета, кликнуть на узел для открытия панели с текстом принятого ответа. Нажать `Esc` или `← Back to chat` для плавного возврата.
   - **Регистрация и профиль:** нажать `Log in` $\to$ `Register`, создать пользователя. Перейти в `Profile`, изменить профессию на `Backend developer`, язык на `Русский`, загрузить файл аватара.
   - **Диалоги:** создать чат, отправить запрос с кодом ошибки, закрепить чат (Pin), переименовать и удалить.
   - **SSO вход:** протестировать авторизацию через кнопку «Войти через Яндекс ID».
3. **Демонстрация Remote MCP в IDE (Cursor / Claude Code):**
   - Открыть модальное окно `MCP` на фронтенде или секцию `#landing-mcp`.
   - Скопировать сгенерированный JSON-конфиг (без токенов авторизации):
     ```json
     {
       "mcpServers": {
         "errorium": {
           "url": "http://localhost:8000/sse"
         }
       }
     }
     ```
   - Добавить конфигурацию в `~/.cursor/mcp.json` (или `claude_desktop_config.json`).
   - Задать в IDE запрос ассистенту: `@errorium Как исправить IndexError: list index out of range в Python?`
   - Ассистент выполняет вызов `errorium_search_solution` и возвращает проверенное решение из базы знаний Stack Overflow.
4. **Демонстрация возможностей администратора:**
   - Авторизоваться под учетной записью первого администратора (`FIRST_ADMIN_EMAIL=admin@errorium.ru`).
   - Запросить системную статистику ядра и перцентили задержек:
     ```bash
     curl -H "Authorization: Bearer <ADMIN_TOKEN>" http://localhost:8000/api/v1/admin/stats
     ```
   - Выполнить горячую перезагрузку индекса без остановки ядра:
     ```bash
     curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" http://localhost:8000/api/v1/admin/index/reload
     ```

## 6. Декларация о боевых интеграциях и секретах

В соответствии с правилами честной академической отчетности:
1. **Отсутствие боевых секретов:**
   В репозитории намеренно не хранятся и не подделываются внешние боевые ключи (`OPENAI_API_KEY`, `GIGACHAT_CLIENT_SECRET`, продакшн SMTP-пароли, клиентские секреты OAuth-приложений).
2. **Штатная локальная работа:**
   Все компоненты системы полностью функциональны в локальном стенде:
   - RAG-оркестратор штатно работает в режиме `stub` (детерминированный синтез) с возможностью мгновенного переключения на `openai` или `gigachat` при указании ключей в `.env`.
   - Почтовый сервис работает через `LogMailer` (ссылки сброса пароля безопасно выводятся в stdout).
   - Инвертированный индекс BM25 и графовая база SQLite `graph.db` собраны локально на реальных данных дампа и корпуса benchmark.
   - Никаких фейковых «заглушек под тесты» нет — все структуры данных, бинарные индексы, gRPC-клиенты и алгоритмы ранжирования являются подлинными.
