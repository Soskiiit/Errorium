# decisions.md — Журнал архитектурных решений (Architecture Decision Records)

## ADR-001: Реализация инвертированного индекса и BM25 с нуля
- **Статус:** Принято (Обязательное академическое требование).
- **Контекст:** Требования курса НИРС на кафедре ИУ5 запрещают использование готовых библиотек ранжирования (Elasticsearch, Lucene, rank-bm25).
- **Решение:** Инвертированный индекс строится с нуля с использованием SPIMI-пайплайна. Ранжирование вычисляется по формуле $IDF(t) = \ln(1 + \frac{N - DF(t) + 0.5}{DF(t) + 0.5})$ с параметрами $k_1 = 1.5, b = 0.75$.
- **Последствия:** Полная прозрачность вычислений, возможность тонкой оптимизации токенизации под стектрейсы, соблюдение правил кафедры.

## ADR-002: Межсервисный протокол на базе gRPC
- **Статус:** Принято.
- **Контекст:** Требуется высокоскоростное сетевое взаимодействие между шлюзом `gateway` и поисковым ядром `search_engine_core` с минимальными накладными расходами на сериализацию.
- **Решение:** Использовать протокол gRPC (HTTP/2) со строго типизированными Protobuf-контрактами (`protos/search.proto`, `protos/graph.proto`).
- **Последствия:** Строгий контракт API, автоматическая кодогенерация клиентов, минимальные сетевые задержки при передаче больших списков релевантных тредов.

## ADR-003: Интерактивный граф связей тредов в результатах поиска
- **Статус:** Принято.
- **Контекст:** Разработчикам требуется возможность исследовать смежные ошибки и решения (например, дубликаты вопросов или темы, на которые ссылаются авторы ответов).
- **Решение:**
  - В ядре поиска накапливается граф связей между самими тредами (вопросами на Stack Overflow), а не абстрактных сущностей.
  - Для хранения связей используется встраиваемая база данных SQLite (`data/index/graph.db`) с индексами по `source_doc_id` и `target_doc_id`. Это обеспечивает быстродействие выборки подграфа ($< 1$ мс) и упрощает протокол взаимодействия между Индексатором и Ядром.
  - В веб-интерфейсе реализуется интерактивный граф связей, встроенный прямо в страницу результатов поиска (`/search`).
- **Последствия:** Уникальное конкурентное преимущество, наглядная визуализация контекста без необходимости строить сложные онтологические связи, надежное хранение без ручного кодирования смещений.

## ADR-004: Аутентификация, SSO и разделение прав (RBAC)
- **Статус:** Принято.
- **Контекст:** Необходим удобный вход для разработчиков без запоминания паролей, защита LLM квот, выпуск персональных API-ключей для MCP и закрытый доступ к панели администратора.
- **Решение:**
  - Реализовать SSO через OAuth2 и OpenID Connect (GitHub, Google, корпоративный IdP).
  - Выпускать пару JWT токенов (Access + Refresh).
  - Реализовать RBAC с ролями `guest`, `developer`, `admin`.
  - Предоставить администраторам доступ к `/admin` для контроля состояния индекса и промптов RAG.
- **Последствия:** Безопасность корпоративного уровня, контроль расхода токенов LLM, гибкость интеграций.

## ADR-005: Интеграция с кодинг-ассистентами через Remote MCP
- **Статус:** Принято.
- **Контекст:** Разработчики пишут код в современных IDE (Cursor, Claude Code, Windsurf) и нуждаются в получении проверенных решений Stack Overflow непосредственно в контекст чата IDE.
- **Решение:** Реализовать поддержку открытого протокола **Model Context Protocol (MCP)** через SSE транспорт на эндпоинте `/sse`.
- **Последствия:** Возможность вызова `errorium` напрямую как Tool Use в AI-агентах.
