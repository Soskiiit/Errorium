# 05-rules-and-data-meaning.md — Смысл данных, источники и правила обработки

## 1. Источники данных и модель Stack Overflow

Основным источником сырых данных является официальный открытый архив Stack Exchange Data Dump (`Posts.xml`, `Tags.xml`, `PostLinks.xml` и вспомогательные таблицы).

### Семантическая модель сущностей
- **Post (Вопрос / Ответ, `Posts.xml`):**
  - `Id`: Уникальный целочисленный идентификатор треда.
  - `PostTypeId`: `1` — Вопрос (Question), `2` — Ответ (Answer).
  - `ParentId`: Идентификатор родительского вопроса (для ответов).
  - `AcceptedAnswerId`: Идентификатор принятого сообществом ответа.
  - `Score`: Баланс голосов (голоса «за» минус «против»).
  - `Title`: Заголовок вопроса.
  - `Body`: Содержимое (HTML со сниппетами `<pre><code>`).
  - `Tags`: Множество тегов в формате `<java><spring-boot><hibernate>`.
- **PostLink (Связи между тредами, `PostLinks.xml`):**
  - `Id`: Уникальный идентификатор связи.
  - `PostId`: Идентификатор исходного вопроса.
  - `RelatedPostId`: Идентификатор связанного целевого вопроса.
  - `LinkTypeId`: Тип связи:
    - `1` (`Linked`) — связанный тред (формирует ребро `LINKED_IN_ANSWER`).
    - `3` (`Duplicate`) — тред-дубликат (формирует ребро `DUPLICATE_OF`).

## 2. Модель графа знаний (Knowledge Graph)

Граф связанных SO-тредов в Errorium строится на основе связей между оригинальными обсуждениями Stack Overflow.

### Типы сущностей (Узлы графа):
- **SO Thread (Тред Stack Overflow):** Единый узел, представляющий вопрос и его лучший/принятый ответ.

### Типы связей (Ребра графа):
- `DUPLICATE_OF`: Тред $A$ помечен как дубликат треда $B$.
- `LINKED_IN_ANSWER`: Тред $A$ упоминается или на него ссылаются в тексте ответа к треду $B$.
