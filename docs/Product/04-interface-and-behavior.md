### Экран 1.2: Чат-экран (`/chats`, `/chats/<id>`) — диалоги с RAG-ассистентом
- **Уникальный адрес диалога:** каждый сохранённый чат авторизованного пользователя имеет канонический URL `/chats/<uuid>` (идентификатор выдаёт `POST /api/v1/chats`). Открытие чата из сайдбара или по прямой ссылке загружает историю через `GET /api/v1/chats/{id}` и выставляет адрес в адресной строке (History API `pushState`).
- **Обратная совместимость:** устаревшие адреса `/chat` и `/chat/<id>` молча перенаправляются на канонические `/chats` и `/chats/<id>` через `history.replaceState`.
- **Новый чат:** кнопка `New chat` (и клик по логотипу) сбрасывает текущий диалог (`currentChatId = null`) и возвращает на hero-экран. Первое сообщение авторизованного пользователя создаёт новый чат на бэкенде и меняет URL на `/chats/<новый uuid>`; последующие сообщения в рамках открытого чата дописываются в него же.
- **Гостевой режим:** неавторизованный пользователь выполняет разовые RAG-запросы (`POST /api/v1/search/rag`) без сохранения диалогов. Каждая отправка запроса начинает новый диалог с чистым контейнером сообщений, а не дописывает предыдущий; URL — `/chats` без идентификатора. Персональная история и уникальные адреса доступны после входа.
- **Кеширование ассетов:** `index.html` подключает `api.js` и `app.js` с версионным query-параметром (`?v=YYYYMMDD_N`); dev-nginx отдаёт статику с `Cache-Control: no-cache`, чтобы браузер не исполнял устаревшую версию SPA.

### Экран 2.1: Star Map — интерактивная карта связей тредов (`/star-map`)
Полноэкранная карта связанных SO-тредов в стиле графа Obsidian, открываемая из RAG-ответа (FR-3.4, FR-3.5).

- **Точка входа:** кнопка `Star Map` с иконкой созвездия в шапке карточки ответа ассистента (`.assistant-card`, справа от заголовка `Errorium RAG Synthesis`).
- **Анимированный переход:**
  - При открытии сообщения чата уходят вверх с fade + scale + blur, prompt bar плавно уезжает вниз и скрывается; карта появляется из легкого увеличения (scale 1.045 → 1) с проявлением из blur.
  - Узлы «рождаются» каскадом (stagger ~45 мс) с ease-out-back масштабированием и свечением, ребра проявляются следом.
  - При закрытии (`Back to chat` / `Esc`) карта растворяется с легким увеличением, чат и prompt bar возвращаются обратной анимацией. Состояние переписки сохраняется.
- **Полотно (Canvas 2D, собственная force-симуляция):**
  - Темный космический фон приложения с мерцающим звездным полем и мягкой синей аурой (дизайн-система Errorium).
  - Цветовое кодирование узлов по FR-3.2: зеленый `#10b981` (Top-1 BM25), желтый `#f59e0b` (Top-K), синий `#38bdf8` (дубликаты), фиолетовый `#a855f7` (ссылки в ответах). Радиус узла $\propto \sqrt{Score}$.
  - Форма узлов: компактные четырёхлучевые звёзды (sparkle) с ядром в виде белой мини-звезды с мягкими размытыми краями (radial gradient с растворением к кончикам лучей + белое свечение), соосно телу; мягким ореолом своего цвета (radial gradient) и лёгким мерцанием; каждая звезда имеет небольшой детерминированный наклон. Радиус: $4 + 0.15\sqrt{Score}$ (clamp $[5, 17]$, $+1.5$ для Top-1). Маркеры легенды повторяют форму звёзд (CSS clip-path + drop-shadow).
  - Прогрессивные подписи: при zoom $\ge 0.7$ появляются сокращённые (~12 символов), на $\ge 1.15$ удлиняются до ~26, на $\ge 1.8$ — до ~48 символов; переходы между ступенями — плавный crossfade. Наведённый/выбранный узел и его соседи подписаны на любом зуме. Числовой рейтинг и индикатор принятого ответа в подписях не отображаются.
  - Ребра: `DUPLICATE_OF` — пунктирные с голубым оттенком, `LINKED_IN_ANSWER` — сплошные с фиолетовым оттенком; при наведении/выборе узла его связи подсвечиваются, остальные затемняются.
  - Физика: кулоновское отталкивание узлов, пружины ребер, центрирование, затухание скоростей; перетаскивание узла «подогревает» симуляцию.
- **Управление:**
  - Панорамирование перетаскиванием фона, zoom колесом мыши / pinch / кнопками `+`, `−`, `⤢` (вписать граф) в правом нижнем углу. Кнопки масштабируют плавно (ease-out анимация ~280 мс, повторные нажатия накапливают зум без рывков); ручное pan / wheel / pinch прерывает анимацию. При `prefers-reduced-motion` зум применяется мгновенно.
  - Перетаскивание узлов; клик (без drag) открывает панель деталей.
  - Подсказка `Drag nodes · Scroll to zoom · Click a star for details` внизу по центру, исчезает после первого взаимодействия.
- **Hover:** стеклянный тултип рядом с курсором: заголовок треда, сниппет и теги (без числового рейтинга и галочки принятого ответа).
- **Click:** правая стеклянная панель деталей: бейдж категории, заголовок, теги, текст лучшего/принятого ответа, кнопка-ссылка `Open on Stack Overflow ↗`, закрытие `✕` (без числового рейтинга и галочки).
- **Легенда:** стеклянная плашка слева внизу с четырьмя категориями узлов (`Top result`, `Top-K results`, `Duplicates`, `Linked in answers`).
- **Шапка карты:** кнопка `← Back to chat`, заголовок `Star Map` и подзаголовок с текстом исходного запроса.
- **Данные:** реальный подграф связанных обсуждений запрашивается из Gateway API через `GET /api/v1/graph/threads?doc_ids=...` (FR-3.5) на основе идентификаторов документов источников карточки RAG-ответа; структура полностью соответствует `ThreadGraphResponse` / `ThreadDetailsResponse`.

### Экран 4: Аутентификация и SSO (`/auth/login`)
- Карточки и кнопки входа:
  - «Войти через Яндекс ID» (OAuth2 — полностью функциональный вход с редиректом и получением токенов в `/auth/callback`)
  - «Войти через GitHub» (OAuth2)
  - «Войти через Google» (OpenID Connect)
  - Стандартная форма входа по email и паролю
  - Восстановление пароля по ссылке через email
- **Восстановление пароля (реальный флоу через API, без моков):**
  - «Forgot password?» (и строка Security в профиле через предупреждающую модалку) открывает модалку ввода email. Отправка вызывает `POST /api/v1/auth/password/forgot`, который всегда отвечает `202 Accepted` (защита от enumeration). После успешного запроса в модалке показывается уведомление «Если этот email зарегистрирован, мы отправили ссылку для сброса» и подсказка проверить папку «Спам». Окно ввода нового пароля автоматически **не открывается** — сброс возможен только по ссылке из письма.
  - Ссылка из письма ведёт на SPA-маршрут `/reset-password?token=...` (одноразовый токен, TTL 1 час, формируется из `FRONTEND_URL`). Маршрут открывает модалку нового пароля; отправка вызывает `POST /api/v1/auth/password/reset` с полями `token` и `new_password` (8–128 символов, подтверждение вторым полем).
  - Успех (`204 No Content`): токен убирается из адресной строки, локальные токены и профиль очищаются (бэкенд отзывает все сессии), показывается тост об успехе и открывается окно входа. `401`: ошибка «Ссылка недействительна или истекла» с предложением запросить новую. Открытие `/reset-password` без токена предлагает запросить ссылку заново.
- Обработка редиректа callback (`/auth/callback`), извлечение токенов из hash-фрагмента (`#access_token=...&refresh_token=...`), сохранение в `localStorage` и обновление состояния интерфейса.

### Экран 6: Панель администратора (`/admin`)
- Доступ только для пользователей с ролью `admin`.
- **Вкладка «Индекс и Движок»:** размер индекса, количество документов $N$, статус сборки индекса, кнопка «Переиндексировать дамп».
- **Вкладка «RAG & LLM»:** выбор активного провайдера (OpenAI, Claude, Local), редактор системного промпта с версионированием, установка max_tokens и temperature.
- **Вкладка «Пользователи и безопасность»:** список зарегистрированных пользователей, роли, принудительный отзыв токенов.
- **Вкладка «Аналитика»:** графики $P_{95}$ задержки, статистика популярных ошибок, отчет по качеству ответов.
