# 03-requirements.md — Требования и критерии приемки

## 1. Функциональные требования (FR)

### FR-1: Поисковый движок и ранжирование
- **FR-1.1:** Парсинг дампа Stack Overflow объемом до 100 ГБ в потоковом режиме без переполнения оперативной памяти.
- **FR-1.2:** Токенизация с выделением технических терминов: языки (`C++`, `C#`), идентификаторы (`NullPointerException`, `ECONNREFUSED`), пути вызовов (`module.submodule.func`).
- **FR-1.3:** Инвертированный индекс собственной реализации (Posting lists: doc_id, tf, позиции токенов).
- **FR-1.4:** Ранжирование BM25 со строгим соответствием методике ИУ5 ($k_1 = 1.5, b = 0.75$).

### FR-2: RAG-синтез
- **FR-2.1:** Формирование сжатого и очищенного от HTML контекста из Top-K документов (где $K \in [3, 10]$).
- **FR-2.2:** Генерация ответов на русском языке с четким разделением на:
  1. Суть и первопричина проблемы.
  2. Готовый блок исправленного кода.
  3. Предотвращение рецидивов ошибки.
- **FR-2.3:** Стриминг ответа пользователю через SSE (Server-Sent Events).

### FR-3: Интерактивный граф связанных SO-тредов
- **FR-3.1:** Автоматическое построение графа тредов на странице результатов поиска (`/search`). Граф представляет собой сеть связанных обсуждений Stack Overflow.
- **FR-3.2:** Визуализация узлов (тредов):
  - Цветовое кодирование: ЗЕЛЕНЫЙ (наиболее релевантный результат BM25), ЖЕЛТЫЙ (другие результаты Top-K), СИНИЙ (дубликаты на SO), ФИОЛЕТОВЫЙ (треды, на которые ссылаются в ответах).
  - Размер узла пропорционален `sqrt(Score)` или `log(Score)` оригинального вопроса.
- **FR-3.3:** Интерактивное поведение:
  - **Hover:** при наведении курсора отображается заголовок, сниппет вопроса и иконка ✅, если у вопроса есть принятый ответ.
  - **Click:** при клике на узел отображается текст лучшего или принятого ответа.
  - Узлы должны содержать прямую ссылку на оригинальную публикацию Stack Overflow.

### FR-4: Аутентификация, SSO и авторизация
- **FR-4.1:** Поддержка SSO входа через протоколы OAuth2 и OpenID Connect (провайдеры: GitHub, Google, корпоративный Keycloak).
- **FR-4.2:** Выдача JWT-токенов с подписью HMAC-SHA256 или RSA.
- **FR-4.3:** Ролевой доступ (RBAC): разделение маршрутов на общедоступные, пользовательские и административные.
- **FR-4.4:** Управление постоянными API-ключами для внешних AI-агентов (MCP).

### FR-5: Панель администратора (Admin Dashboard)
- **FR-5.1:** Просмотр статистики поискового ядра: размер индекса, время поиска ($P_{50}, P_{95}, P_{99}$), объем памяти.
- **FR-5.2:** Управление учетными записями, блокировка пользователей, назначение роли администратора.
- **FR-5.3:** Управление параметрами LLM: выбор модели, редактирование системного RAG-промпта, установка лимитов токенов.
- **FR-5.4:** Триггер переиндексации дампа или горячей перезагрузки индекса ядра без простоя.

## 2. Нефункциональные требования (NFR)

| Метрика | Требование | Метод валидации |
| :--- | :--- | :--- |
| **Время ответа поиска (Search Latency)** | $\le 150$ мс для $P_{95}$ (Top-10 выборка) | Бенчмарк на выборке 10 000 запросов |
| **Точность ранжирования** | $Recall@10 \ge 0.75$, $MRR \ge 0.50$ | Скрипт `benchmark/evaluate.py` |
| **Потребление RAM индексатором** | $\le 4$ ГБ в процессе потокового парсинга 100 ГБ | Профилирование контейнера через `docker stats` |
| **Отказоустойчивость** | Недоступность LLM-провайдера не должна ломать базовый поиск по BM25 | Тест изоляции `tests/integration/test_rag_fallback.py` |
| **Академическая чистота** | 0% сторонних библиотек поиска (Elasticsearch, Lucene, rank-bm25) | Статический аудит зависимостей проекта |
